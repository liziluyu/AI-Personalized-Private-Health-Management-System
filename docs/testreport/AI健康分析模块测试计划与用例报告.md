## 一、测试计划
### 1.1 测试目的
验证AI健康分析模块的健康画像生成、健康计划生成、健康知识推送功能是否符合需求规格说明书与设计文档要求，确保AI服务调用链路通畅、生成内容格式正确、数据持久化存储准确、异常场景提示友好、权限校验生效，为联调测试与项目验收提供质量依据。

### 1.2 测试范围
#### 1.2.1 覆盖功能点
- **Must级**：AI健康画像生成（时间范围选择7/30/90天、风险等级展示、健康标签着色、综合分析报告渲染）、AI健康计划生成（快捷选项输入、自定义文本输入、饮食/运动/睡眠三栏建议展示、计划反馈提交）
- **Should级**：健康知识库检索（关键词搜索、标签筛选、分页）、AI知识推送生成、推送已读标记、知识详情弹窗
#### 1.2.2 不覆盖范围
- 健康数据的手动录入、删除、批量导入（归属健康数据管理模块）
- 健康趋势图表渲染、统计指标计算、报告导出（归属健康可视化模块）
- 管理员用户管理、平台数据统计（归属管理员模块）
- AI对话/咨询功能（`ai_consult`表为扩展表，尚未启用）

### 1.3 测试环境
| 环境项 | 配置说明 |
| ---- | ---- |
| 操作系统 | Windows 10 及以上 |
| 浏览器 | Edge 最新版 |
| 后端服务 | Spring Boot 3.5.7，服务端口 8080 |
| AI服务 | FastAPI（Uvicorn），服务端口 30000 |
| AI模型 | DeepSeek API（`deepseek-v4-pro`），通过 `.env` 中 `AI_API_KEY` 配置 |
| 数据库 | MySQL 8.4，执行最新建表与初始化脚本 |
| 前端环境 | Vue 3.5，关闭 Mock 模式（`VITE_MOCK_API=false`） |
| 代码分支 | `dev` 分支最新代码 |
| 测试账号 | 预置普通用户测试账号（USER角色），账户内含多类历史健康数据（约100条，覆盖5项指标，跨度90天）；新注册无数据账号用于边界测试 |

### 1.4 测试策略
1. **测试类型**：黑盒功能测试、接口一致性校验、数据库数据核对、AI输出质量评估、权限安全测试
2. **设计方法**：等价类划分法、边界值分析法、异常场景法、数据比对法、安全渗透测试法
3. **执行优先级**：
   - P0（最高）：画像生成、计划生成、核心展示校验（Must级核心功能）
   - P1（次高）：知识推送、权限校验、边界异常场景、反馈提交（Should级功能）
   - P2（一般）：极端数据量、并发场景、重复操作幂等性
4. **执行方式**：前端页面操作 + 接口返回数据校验 + 数据库原始数据三方比对 + FastAPI /docs 接口单独验证

### 1.5 缺陷管理规范
1. **缺陷分级**
   - 严重：AI服务调用崩溃、画像/计划生成功能阻断、数据存储丢失、权限越权漏洞
   - 一般：AI返回内容格式异常、生成超时无反馈、筛选/分页失效、已读状态同步错误、风险等级着色错误
   - 轻微：样式细节问题、加载动画不流畅、文案不规范、提示不友好、输入校验覆盖不全
2. **闭环流程**：缺陷登记 → 分配对应开发修复 → 修复后拉取最新代码复测 → 复测通过关闭缺陷 / 不通过退回重改

### 1.6 测试通过标准
1. Must级功能无严重、一般级别缺陷，轻微缺陷不超过2个；
2. Should级功能无严重级别缺陷，一般缺陷不超过2个；
3. AI服务全链路调用通畅（Spring Boot → FastAPI → DeepSeek API → 结果），画像/计划生成成功率≥95%；
4. 生成内容写入数据库正确（`health_profile`、`health_plan`、`knowledge_push`表数据完整准确）；
5. 权限校验生效，未登录用户无法访问AI分析页面与接口，无越权漏洞；
6. 极端负面关键词被过滤，输入内容不导致系统异常。
